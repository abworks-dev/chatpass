# 客户端接入与手动验收

## 共同前提

本文件给出协议配置条件，**不是已经验证的 Hermes/OpenClaw/DeepSeek Harness 配置文件**。具体 provider 字段由实际安装版本决定；不写猜测性的配置项，不改动现有客户端凭据。

- ChatPass 正在同一台电脑运行，默认地址 `http://127.0.0.1:19840/v1`。
- API Key 为显式创建的 `cp_` 网关密钥，不是 OAuth token。
- 模型 ID 取自鉴权后的 `GET /v1/models`；不要假定所有账号有相同模型。
- provider 必须调用原生 Responses API，并接受流式 SSE。
- 多轮/工具轮须显式提交完整历史，包括工具调用、匹配的 `call_id`、工具结果和必要 reasoning 项。
- provider 不得强制发送当前预览禁止的字段，例如 `previous_response_id`、`temperature`、`max_output_tokens`。收到 `unsupported_capability` 应核对协议，不加静默丢字段补丁。

如果客户端版本只支持 `/chat/completions`，本版不能直接接入。先确认接口能力，不靠更改模型名冒充兼容。

## 按客户端检查

| 客户端 | 必须确认 | 当前状态 |
| --- | --- | --- |
| Hermes Agent | 自定义 base URL/key、原生 Responses 路由、完整工具历史 | 未实测 |
| OpenClaw | provider 的 API 类型为 Responses，模型定义和历史参数符合预览协议 | 未实测 |
| DeepSeek Harness | 配置的 Responses adapter 使用本地 URL，保留工具/reasoning 项，不附加禁止字段 | 未实测 |

接入时记录客户端版本、provider 类型及实际请求字段。不要让客户端复用原有 Codex 登录 token；凭据由 ChatPass 独占管理。

## 手动验收顺序

1. **账号授权**：手动运行 `chatpass login`；检查官方域名和授权范围。取消后不得显示授权成功。
2. **模型发现**：正确网关密钥能返回 `data[].id`；错误密钥返回 401；模型列表不是硬编码。
3. **单轮流式**：选择实际模型，输入短问题；可见增量及最终 `response.completed`。部分文本加 EOF 不算完成。
4. **多轮**：第二轮带完整第一轮历史；确认能引用先前内容，不使用 `previous_response_id`。
5. **工具轮**：定义无副作用的测试函数；首轮得到结构化函数调用，执行本地测试工具，追加工具结果，再收到最终回答。
6. **reasoning**：若模型返回 reasoning 项，后续完整历史不得丢弃这些项；不要求所有模型都返回。
7. **失败与恢复**：无效模型、禁止字段、授权拒绝、额度错误、取消请求分别有明确结果；取消不会继续占用并发槽。不得把异常流当成功。
8. **密钥轮换**：显式轮换后，旧密钥失败，新密钥可用。
9. **三客户端分别重复**：每个客户端记录版本与结果；不能用一个客户端的成功证明另两个成功。

账号资格和扣减规则须依据官方账号侧观测核实；模拟 token、模型目录和 SSE 只能证明网关处理逻辑。不要为验证重试消耗额度的推理，或把未观测到收费当成“无限免费”。

## 排错

- 404 `/chat/completions`：客户端接口类型不对；当前没有转换适配器。
- 400 `unsupported_capability`：检查 `error.param` 对应的字段及客户端发送行为。
- 401：先区分本地 `cp_` 密钥失效与上游授权失败。
- 403/429：检查账号资格/权限和额度；不换到按量付费账户。
- `login_required`：刷新结果不确定或凭据失效，需要手动重新登录。
- 待验证令牌状态：先恢复网络/JWKS 可访问性；不要删除加密检查点或重发旧刷新令牌。

请只报告非敏感版本、错误码和请求字段名。不要发布密钥、token、回调链接、完整个人对话或原始上游错误正文。

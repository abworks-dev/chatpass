# 本地 Web 管理台

## 运行与权限流

`uv run chatpass web` 同时运行管理台和原有 Responses 网关；`serve` 仍是纯 API 模式。默认地址为 `http://127.0.0.1:19840/`，仅接受配置中的字面回环地址和端口。不能通过任意 localhost 别名、DNS 重绑定域名、反向代理或公网隧道访问管理台。

管理权限流：终端生成随机单次入口 → 用户打开带 fragment 的链接 → 页面先清除 fragment 再向同源会话接口交换 → HttpOnly / SameSite=Strict 管理 Cookie → 带同源 Origin 和内存 CSRF token 的操作。入口五分钟过期，会话八小时过期；进程重启使两者失效。管理 Cookie 仅用于 `/admin`。网关 `cp_` 密钥用于 `/v1`，不能登录管理台。

管理入口是敏感的短期管理能力。终端默认明确显示它，但 HTTP 访问日志关闭、fragment 不发送给服务器。不要公开终端截图、入口链接或一次显示的网关密钥。同一个系统用户下的恶意软件不在本项目隔离范围内。

## 页面与操作

- **概览**：非敏感授权、密钥、待验证状态；运行时间和当前进程推理接口请求计数。计数重启归零，不是账号总用量、官方额度或账单。
- **账号授权**：用户明确点击才启动官方授权浏览器；同时仅允许一个登录操作。管理台展示等待、成功、失败，不取得授权 URL、回调 URL、access/refresh/ID token。没有自动导入外部工具凭据或自动登录。
- **网关密钥**：未配置时显式创建；已配置时不能再次初始化。轮换须确认旧客户端立即失效；密钥只在本次响应中显示，不在状态接口或浏览器存储中保留。
- **模型目录**：用户主动查询，同一上游协议所有者负责读取和验证；查询失败不展示猜测模型。不自动发送推理请求。
- **客户端接入**：显示本机 Base URL、Responses 协议要求和未实测状态；不虚构 Hermes、OpenClaw 或 DeepSeek Harness 的成功配置。

## 凭据与配置边界

现有 `StateStore` 是加密磁盘状态与系统 keyring 的唯一所有者；现有 `Credentials` 是刷新/验证所有者；现有 `login` 是交互授权所有者。管理台复用它们，不额外保存 OAuth 状态，不新建明文配置，不把 OAuth 值返回浏览器。推理模型查询共享网关的固定上游地址、目录校验、限额与安全错误处理。

没有新增环境变量或秘密文件。可沿用全局 `--data-dir`，所有命令必须指向相同目录。管理 bootstrap、session 和 CSRF 只在服务进程内存中存在，不持久化。初次读取状态可能创建系统 keyring 主密钥；没有受支持 keyring 时应显示存储错误，不回退到明文或伪装成正常状态。

本版没有账号删除、撤销上游授权、配置编辑、多用户、进程启停或公网部署面板。会话过期后需要新的单次入口，而非用网关密钥解锁。

## 静态资源与第三方许可

基于 Tabler 1.6.1 的布局与 CSS 改造。只引入固定版本样式表；不加载模板 JavaScript、其他附带库、遥测、CDN 或远程字体。原版权头和完整 MIT 文本随包提供，详见 [第三方声明](../THIRD_PARTY_NOTICES.md)。这不改变 ChatPass 本身尚未选定许可证的状态。

页面采用独立脚本与样式、同源 CSP、禁止 framing、no-referrer 和管理响应 no-store。模型及错误内容以文本插入，不能作为 HTML 执行。

## 验证边界

自动验证和浏览器证据记录在 [验证说明](verification.md)，开发测试入口是 [管理台测试](../tests/test_console.py) 和 [浏览器测试](../tests/test_web_browser.py)。浏览器测试使用独立临时加密状态、测试 keyring、模拟官方模型响应和模拟登录结果；不得把这些截图或成功状态解释为真实账号验证。

真实授权、模型可用性、额度与三个客户端仍需用户主动授权后实测。管理台可交付与真实官方服务验收是两个不同结论。

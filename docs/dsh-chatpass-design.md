# ChatPass + dsh-chatpass 设计方案

状态（2026-10-18 文档校正，未新增运行验收）：设计已批准进入阶段 0/1 实现，见[实施计划](dsh-chatpass-implementation-plan.md)。连接模式 alpha 已实现至隔离验证停止点，当前源码版本为 `0.1.0-alpha.3`，已记录构建、隔离回归及打包客户端检查；该版本实际安装、冷启动、双入口交互和真实上游验收仍待验证。阶段 2/3 托管与安装辅助不属于本次已实现范围。版本化结果以[实施与修复证据](aegis/work/2026-10-14-dsh-chatpass/90-evidence.md)为准，不将设计批准或构建成功等同于发布、稳定可用或真实账号验证。

## 1. 已确认方向与批准边界

用户选择保留 ChatPass 核心、增加 DSH 连接插件，并接受首个可用版本需要用户自行启动 ChatPass，后续再增加托管模式。该设计确认本身不是实际账号操作、配置变更、安装、升级或发布授权；后续安装尝试的单独授权与结果见版本化实施证据。以下阶段 0/1 契约已作为实施计划基线，托管与安装辅助仍为后续设计；已实现范围及未覆盖项以实施证据为准。

目标：在 DSH 中配置连接、发现模型、选择模型、执行原生 Responses 请求、查看安全诊断；继续支持其他网关客户端。核心仍是授权、凭据、刷新、上游访问和协议适配的唯一所有者。

非目标：多账号池、自动切号、收费 API fallback、Codex 私有后端、凭据导入、公网接入、远程浏览器授权、自动改默认模型/搜索路由、完整 OpenAI API 兼容性、官方额度推测。

## 3. 架构与责任

```text
DSH 浏览器 -> DSH 已认证插件接口 -> dsh-chatpass 宿主
                                      | HTTP 模型目录/Responses
                                      v
                               ChatPass 核心 -> OpenAI 公共上游
```

第二阶段增加宿主到自己启动核心的私有 IPC，仅用于控制操作。

- 核心：OAuth、OIDC、账号身份、keyring、加密状态、刷新、模型发现、上游请求与流验证。
- 插件宿主：连接配置、秘密引用、provider 注册、DSH 消息映射、诊断；第二阶段管理自有核心进程。
- 插件前端：输入和状态展示，不持有上游凭据，不直连核心管理 API。
- DSH：Agent 循环、工具执行/审批、附件、会话、压缩、持久化和恢复。

独立 provider 标识建议为 `chatpass`，不得占用 `openai-codex`。复用 DSH 已有 Responses 适配器优先；若宿主扩展契约不足，只增加薄消息映射层，不复制核心归一化或 OAuth。

## 4. 首版：连接模式

用户自行运行现有 ChatPass。插件不接管、停止或升级外部服务。

配置：模式 `connect`；本机 API 地址（默认 `http://127.0.0.1:19840/v1`）；网关密钥秘密引用。输入仅接受明确本机回环目标；首版建议限定 `127.0.0.1`，IPv6 须在目标宿主独立验证后支持。不接受用户信息、fragment、任意路径、DNS 别名、非回环地址或跳转。网关访问绕过外部代理，不允许重定向把密钥带到别处。

沿用 `GET /v1/models` 和流式 `POST /v1/responses`。模型目录检测是用户主动网络操作，可能触发核心凭据刷新，但不发送推理。连接模式不调用管理接口；无密钥公开探针如未来新增，只返回有界非敏感版本信息，不能作为服务身份信任依据。

连接流程：填地址和密钥 -> 显式测试连接 -> 发现模型 -> 用户选择模型。发现结果可复用首次测试的模型目录，避免重复调用。

现有单次管理入口不能从地址推导。插件显示如何使用核心启动时生成的私有入口，不声称首页即可管理，不保存或收集该入口。账号授权/注销仍在现有管理台或 CLI 完成。

网关密钥只用于推理/模型访问。不得自动创建替代密钥或轮换全局密钥，避免其他客户端失效。

## 5. 秘密与配置

OAuth token 从不交给插件或浏览器，不进入 DSH provider 配置、日志、诊断报告。

连接模式网关密钥：前端提交后清空，仅显示“已配置”；宿主保管。优先使用满足要求且经核验的 DSH secret 接口；没有安全持久化能力时只提供内存模式或推迟持久化，不采用明文 fallback。必须核验秘密是否会进入配置备份、导出、同步和工具可读配置。

非秘密配置与秘密引用分开。地址、端口、模式可以持久化；原始密钥不进入 localStorage、URL、日志或常规配置。内存模式须明确说明重启后重新输入。

修改配置：新配置验证失败保留旧配置和用户非敏感输入；成功后仅影响后续请求。正在执行的请求使用已捕获配置，不能半途换端点/密钥。删除连接仅删除插件配置/秘密引用，不撤销核心授权。

## 6. DSH 模型与请求契约

只显示核心返回的模型 ID。缓存注明时间及过期状态；刷新失败不伪造新鲜成功。目录可见不等于账号资格或额度证明。

目录缺失上下文、输出限制、图片能力时不得照搬 Codex 数值。实施验证需要确认 DSH 对未知元数据的契约；如必须提供值，只使用可溯源、标注的显式配置，不把假定能力标为上游已验证。

完整历史、工具调用 ID、参数、结果关联和 opaque reasoning 保留；禁用服务器状态引用。DSH 内部 system/developer 与工具结构映射须通过实际宿主适配器测试。仅当支持已确认才展示自定义工具/图片等能力。

取消传播到 HTTP 和核心；截断或非成功终态必须失败。不得重放已发送推理，不因 429 切账号、模型或付费 API。重连只用于下一次请求/状态查询。

模型选择与设置默认分开。安装不改变默认模型、搜索或其他 provider。

## 7. 界面与状态

用户已确认双入口布局：设置 -> 模型 中的 ChatPass 卡片，以及设置 -> 内置插件 中的 ChatPass 专属设置页。不新增顶层设置导航，不嵌入独立管理台。

参考本机 dsh-codex-connect 的前端注册实现：模型页使用 `settings.models.footer` 扩展卡片，插件页使用 `settings.plugins.tab` 注册专属设置页；两处注入同一配置和状态所有者。具体槽位在目标 DSH 版本上仍需验证，插件页的显示位置/名称以宿主为准。

- 模型页卡片：连接状态、地址摘要、最近一次模型发现结果、刷新模型、授权操作说明及“更多设置”。未配置时提供“配置连接”，打开共享连接表单。模型使用仍走 DSH 原生选择器，不在卡片另建一套默认模型设置。
- 内置插件页：完整连接表单（地址、秘密密钥输入/更换、验证并保存）、模型发现状态、账号操作说明、折叠的高级设置和诊断、明确的移除连接操作。首版不显示托管启停/登录/注销等未实现按钮，也不提供会误改全局网关密钥的轮换按钮。
- 模型页“更多设置”可采用 Codex Connect 类似的原生模态框，复用完整设置组件；如果宿主提供可靠的设置页导航，可直接定位内置插件页。两种入口都不得各写配置。具体呈现由阶段 0 验证确定。
- 两处读取同一宿主配置、连接状态和模型目录；保存后同步更新。未保存内容属于表单草稿，不当作运行配置；失败保留草稿，关闭有未保存更改时提供放弃/继续编辑提示。并发修改使用宿主修订号/冲突机制，拒绝静默覆盖；如该机制不可用，先固定单写入口再发布。
- 密钥只在本次输入过程中存在于前端，保存后清空，两处均只显示“已配置”。状态不得因浏览器页面切换而触发重复验证、模型刷新或推理。

第二阶段托管模式在相同两处增加运行和授权状态：模型页保留高频操作，内置插件页承载完整管理与诊断；不会另起第三个控制台。

三个独立维度：
- 核心：未配置、检测中、可连接、离线、不兼容。
- 授权：连接模式不能凭 HTTP 在线推测已授权；以经过认证的实际结果显示已验证/需授权/未知，不伪装拥有完整管理状态。
- 请求：完成、取消、超时、限流/额度、资格不足、协议失败。

错误指引区分本地密钥 401 与上游授权失败。保留有界 allowlist 错误字段，不展示任意远端正文。

测试连接不发推理；消耗额度的短推理测试需独立按钮、明确说明和用户操作。控件支持键盘、焦点反馈、非颜色状态表达；检查长模型名、空目录、加载、失败、深浅主题及窄屏。

诊断默认本地；只导出 allowlist 版本、状态、错误类别。地址/路径/请求 ID 等可识别字段按必要性脱敏并供用户预览，不导出 token、密钥、授权 URL、邮箱、完整会话或上游原文。

## 8. 第二阶段：托管模式（不纳入首版）

用户明确选择 `managed`。先托管已安装核心，再增加确认后的安装辅助。无需首版捆绑 Python。

私有 IPC 推荐子进程 stdio 上有界 JSON 消息：请求 ID、协议版本、严格字段/操作校验、大小/并发/时间限制；stdout 仅协议，stderr 脱敏日志。禁止任意 shell/文件读取命令。

拟议操作：`hello`、`status.get`、`auth.start`、`auth.operation.get`、`auth.logout`、`runtime.shutdown`。操作开始需用户明确操作；断开/超时不自动重发副作用，需 operation ID/结果查询和“结果未知”恢复语义。授权 URL 与回调处理遵循核心已验证管理安全契约，不经普通状态/日志泄漏。

在 Windows/Desktop 验证宿主子进程 IPC 能力。当前工具沙箱命名管道/stdio 捕获限制不等同插件运行时；不能承诺可用或要求关闭沙箱掩盖缺口。如果验证不满足，保持连接模式可交付，另行审阅替代控制通道，而非临时开放高权限 HTTP。

核心生成仅内存的本实例推理密钥，经 IPC 给插件宿主；仅 /v1 权限，退出失效，不替换持久化全局密钥。现有密钥继续有效。该认证扩展由核心负责，需独立安全审阅。

实例归属由子进程句柄、随机实例 ID 和握手共同确认。端口/PID 不足以证明归属。不接管外部服务、不杀占用进程；端口冲突提供连接已有服务或改端口。按数据目录约束托管实例，防重复启动；锁边界、异常恢复需阶段 2 详细契约。

启动使用绝对执行路径及参数数组，不拼 shell。正常停止先拒新请求、排空；强制停止提示会影响该核心其他客户端。停用只关自有子进程；卸载不删除授权、加密状态或 keyring 主密钥。第一版托管不自动崩溃重启。宿主退出后的孤儿进程退出策略、刷新/注销进行中关闭策略需要在阶段 2 固定并测试。

首期仅本机浏览器/宿主；远程浏览器授权另行设计。

## 9. 安装、升级与发布

建议同仓开发、分开发布：保留 Python 核心，新增 `plugins/dsh-chatpass/` npm 包。组件边界：宿主入口、HTTP 客户端、provider、秘密/配置、前端、诊断；阶段 2 增加运行控制。

核心 Web 与 IPC 应调用同一操作所有者；不要模拟管理台 Cookie，也不要新增第二套刷新/状态机。现有 SIWC 工作先固定基线或协调完成。

独立兼容矩阵：插件/DSH、插件/核心协议、核心/上游。公开已验证精确组合；包声明范围不等于测试证明。插件版本与核心版本可独立。

安装辅助仅用户确认后执行，固定经验证核心版本、独立运行环境，不修改系统 Python、不在普通启动时安装/升级、不执行未验证 latest。安装失败保留旧可用版本。数据目录不位于 npm 包或插件安装目录。

升级不自动迁移或删除凭据。遇不可逆状态迁移需要明确备份、版本与回退设计，另行批准。

## 10. 分阶段验收

### 阶段 0：接口与基线验证

确认目标 DSH 版本、provider 注册、Responses 复用、模型元数据契约、安全 secret 能力、IPC 可行性和 SIWC 基线。只读或隔离 mock 验证，不操作真实账号。产出验证证据和支持范围。

### 阶段 1：连接模式 MVP

- 与 Codex Connect 共存，不改变默认模型/搜索。
- 已有网关接入，错误密钥明确失败，非回环/重定向拒绝。
- 真实目录、缓存标记、刷新失败恢复。
- 流式单轮/完整多轮、函数调用结果、并行工具、opaque reasoning、取消。
- 超时、上游授权/资格/429、截断/失败终态正确，不假成功或重放。
- 配置热更新不改变在途请求；秘密安全与备份/导出边界可检验。
- 停用/卸载不停止外部核心、不改核心密钥或授权。
- UI 空/等待/失败/恢复、键盘及窄屏有明确测试。

### 阶段 2：托管核心

验证实例归属、就绪、冲突、多宿主、异常退出、IPC 断开与操作未知、关闭中的刷新、内存密钥失效、不影响持久化密钥、注销明确后果及卸载保留凭据。先固定详细协议再实施。

### 阶段 3：安装辅助与发布

验证隔离安装、固定版本、失败回退、兼容矩阵、包内容不含秘密、正式安装测试。实际账号授权、目录、短推理、工具轮、取消/恢复需用户参与并记录版本；mock 成功不替代真实验收。

非流式终态 output 缺口已完成本地修复及模拟验证，但新版真实非流式／Chat 验收尚未完成，因此仍不宣称完整真实兼容性。插件隔离测试也不能替代核心新版与实际客户端的联合验收。

## 11. 已批准范围、待验证项与停止条件

已确认并进入阶段 0/1 实施：核心 + 连接插件；首版自行启动核心，独立 `chatpass` provider、仅本机回环、同仓分包与双设置入口共享状态。当前实现将配置及密钥都仅保存在内存中；未验证安全持久化能力，不提供明文持久化 fallback。模型容量由用户显式配置，不把目录或 SDK 占位值当作上游能力证明。

隔离验证已覆盖目标 SDK 接口与打包客户端；真实宿主挂载、认证/来源拒绝、浏览器交互及上游互通仍待验证。阶段 2 私有 IPC 与内存推理密钥仍属后续设计，其详细协议、可行性与安全语义须另行验证。

首版停止条件：连接模式交付且上述可测验收通过，公开真实验收缺口；不为完成首版自动扩展到托管/安装。

风险停止条件：无法安全保存秘密则不做明文持久化；无法保留 DSH 历史/取消语义则暂停 provider 发布；IPC 不可行则不推进托管控制；上游权限/额度不明不得虚构。
